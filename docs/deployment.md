# Deployment

This doc covers local commands, verification, static export, and Cloudflare Pages.

## Commands

```bash
npm run dev
npm run typecheck
npm run build
```

`next-env.d.ts` should stay in the repo. It is generated by Next, referenced by `tsconfig.json`, and provides Next/Image/global route type declarations.

## Static Output

- `public/` stores original/static site assets and remains the Next.js static asset input.
- `out/` remains generated static export output and can hold optimized generated images later.

Next.js does not allow `public/` as the static export output directory, because `public/` is reserved as an input folder.

`out/` is ignored by git.

## Cloudflare Pages

Recommended Cloudflare Pages settings:

```text
Build command: npm run build
Build output directory: out
Root directory: /
```

No Worker, adapter, or server runtime is required for the current static-export architecture.

Optional Cloudflare files can be added later if needed:

- `public/_headers` for cache or security headers
- `public/_redirects` for redirects
- `wrangler.toml` only if deploying/configuring through Wrangler

## Static Export Constraints

Avoid while `output: "export"` is enabled:

- route handlers
- runtime APIs
- dynamic OG routes
- ISR
- server-only request-time filesystem work

Build-time filesystem usage is allowed through `src/lib/content.ts`.

## Verification

Expected checks:

```bash
npm run typecheck
npm run build
```

The static export should generate routes for the home page, posts, nested posts, global tag pages, projects, and nested project detail pages.

Nonexistent static routes should fall through to the generated `404.html`, which is backed by `src/app/not-found.tsx`.
